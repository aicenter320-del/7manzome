# وضعیت فعلی پروژه

> این فایل کوتاه‌ترین راه برای فهمیدن «الان کجای کار هستیم» است.
> **در پایان هر تسک اجباراً به‌روز می‌شود.** اگر این فایل کهنه باشد، کل سیستم مستندات بی‌ارزش می‌شود.

**آخرین به‌روزرسانی:** زبان بصری Liquid Glass روشن طلایی (ADR-0011)؛ تم فقط روشن؛ هدر کپسولی و منوی موبایل. `npm run verify` باید سبز باشد.

---

## در یک نگاه

هفت منظومه یک طلافروشی آنلاین تخصصی کودکان است که زیر پوسته آن یک پلتفرم «گنجینه طلای کودک» ساخته می‌شود.
والدین و اطرافیان کودک به‌جای هدایای مصرفی، طلا می‌خرند و به مرور یک دارایی واقعی برای کودک می‌سازند.

## استک فنی قطعی‌شده

| لایه | انتخاب | دلیل |
| --- | --- | --- |
| فریم‌ورک | Next.js 16.3 (App Router) | فول‌استک، Server Actions، سئوی خوب |
| زبان | TypeScript در حالت strict | خطاهای مالی نباید در زمان اجرا کشف شوند |
| دیتابیس | SQLite | سادگی عملیاتی، بدون سرور جدا |
| ORM | Drizzle + `@libsql/client` ۰.۱۷ | بدون ماژول نیتیو؛ بین ویندوز و لینوکس rebuild نمی‌خواهد |
| استایل | Tailwind CSS v4 + Liquid Glass روشن طلایی در `shared/ui` | کنترل RTL، توکن برند، شیشه بدون دارک‌مود |
| فونت | وزیرمتن (لوکال) | بیلد نباید به سرور گوگل وابسته باشد |
| احراز هویت | OTP پیامکی + کوکی امضاشده با `jose` | استاندارد بازار ایران |
| پرداخت | فقط کارت‌به‌کارت (فعلاً) | درگاه آنلاین هنوز گرفته نشده |
| اعتبارسنجی | Zod v4 | مرز ورودی همه اکشن‌ها |
| تست | Vitest + Playwright | دامنه و مسیرهای حیاتی |

## چه چیزی ساخته شده است

دوازده ماژول دامنه با وضعیت ✅ در [`01-architecture/module-registry.md`](01-architecture/module-registry.md).
پانزده قابلیت MVP در [`07-roadmap/mvp-checklist.md`](07-roadmap/mvp-checklist.md) تیک خورده‌اند.

لایه `src/app/` مسیرهای عمومی، ورود، داشبورد والد، صفحه هدیه مهمان، پنل ادمین،
سرو فایل و QR را روی API عمومی ماژول‌ها می‌سازد. داده اولیه با `npm run db:seed`
سوپرادمین (`09120000000`)، قیمت طلا، حساب بانکی، کاتالوگ نمونه و صفحات محتوا را می‌سازد.

تسویه پرداخت در ماژول `admin` است (`reviewAndSettlePayment`) تا `payments` به
`orders`/`gifting` وابسته نشود و گراف ماژول‌ها دور نگیرد.

کامپوننت‌های `"use client"` از `index.ts` ماژول‌ها import نمی‌کنند؛ فقط از `ui/`،
`actions/` یا `domain/` تا `server-only` وارد باندل مرورگر نشود. بیلد production و
CI گیت‌هاب (`.github/workflows/verify.yml`) این را قفل کرده‌اند.

ورود توسعه: با `SMS_PROVIDER=console` و `DEV_EXPOSE_OTP=true` کد یک‌بارمصرف در ترمینال
(و در صورت فعال بودن روی صفحه ورود) دیده می‌شود.

## تصمیم‌های قطعی که نباید دوباره باز شوند

این‌ها با ADR ثبت شده‌اند و تغییرشان نیازمند ADR جدید است:

- **هیچ عدد اعشاری در محاسبات مالی.** پول = ریال صحیح، طلا = میلی‌گرم صحیح. ([ADR-0004](06-decisions/0004-integer-money-and-gold.md))
- **دفتر کل طلا فقط append-only است.** موجودی هرگز مستقیم آپدیت نمی‌شود. ([ADR-0005](06-decisions/0005-append-only-gold-ledger.md))
- **کودک ≠ مالک قانونی دارایی.** سه مفهوم جدا: کودک، دارنده حساب، مالک دارایی. ([ADR-0006](06-decisions/0006-ownership-separation.md))
- **قیمت هنگام ثبت سفارش قفل می‌شود** و کل ریزمحاسبات ذخیره می‌گردد. ([ADR-0007](06-decisions/0007-price-lock-on-order.md))
- **ماژول‌ها از طریق `index.ts` به هم وصل می‌شوند**؛ استثنای کلاینت در [`overview.md`](01-architecture/overview.md). ([ADR-0002](06-decisions/0002-modular-architecture.md))

## نقاط باز و ریسک‌ها

| موضوع | وضعیت |
| --- | --- |
| درگاه پرداخت آنلاین | هنوز گرفته نشده؛ فقط پورت و اسکلت آماده است |
| منبع رسمی قیمت طلا | تعیین‌نشده؛ فعلاً ورود دستی توسط ادمین |
| مدل حقوقی موجودی طلای دیجیتال | نیازمند بررسی حقوقی؛ در MVP فقط «انتساب» است نه مالکیت |
| فروش/بازخرید طلا از کاربر | خارج از دامنه MVP ([ADR-0009](06-decisions/0009-out-of-scope-mvp.md)) |

## دستورهای پرکاربرد

```bash
npm run dev          # اجرای محیط توسعه
npm run verify       # تایپ‌چک + لینت + بررسی معماری + تست (قبل از هر کامیت)
npm run build        # بیلد production
npm run test:e2e     # تست Playwright (بعد از build)
npm run db:generate  # ساخت فایل مایگریشن از تغییرات اسکیما
npm run db:migrate   # اعمال مایگریشن‌ها روی دیتابیس
npm run db:seed      # پر کردن دیتابیس با داده اولیه
npm run db:studio    # مرورگر گرافیکی دیتابیس
npm run db:backup    # بکاپ SQLite با VACUUM INTO
```
