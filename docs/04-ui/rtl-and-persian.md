# قوانین RTL و زبان فارسی

## جهت

`<html lang="fa" dir="rtl">` در لایوت ریشه تنظیم شده است.

علاوه بر آن، `DirectionProvider` از Radix در `shared/ui/providers.tsx` قرار دارد.
**این لازم است** چون Radix جهت را از context می‌خواند نه از DOM؛ بدون آن جهت کلیدهای
جهت‌دار صفحه‌کلید و محاسبه موقعیت منوها اشتباه می‌شود.

## کلاس‌های منطقی، نه فیزیکی

هرگز کلاس جهت‌دار فیزیکی ننویسید.

| ننویسید | بنویسید |
| --- | --- |
| `ml-2` `mr-2` | `ms-2` `me-2` |
| `pl-4` `pr-4` | `ps-4` `pe-4` |
| `left-0` `right-0` | `start-0` `end-0` |
| `text-left` `text-right` | `text-start` `text-end` |
| `rounded-l-md` | `rounded-s-md` |
| `border-l` | `border-s` |
| `translate-x-4` | با واریانت `rtl:`/`ltr:` صریح مدیریت کنید |

`translate-x` استثناست، چون Tailwind معادل منطقی برای آن ندارد.
در چنین مواردی از واریانت‌های `rtl:` و `ltr:` استفاده کنید (مثال در `shared/ui/switch.tsx`).

## ارقام

- **تمام اعداد قابل‌مشاهده کاربر با ارقام فارسی نمایش داده می‌شوند.**
- تبدیل با `toPersianDigits` از `shared/lib/persian.ts`.
- ورودی‌های عددی کاربر با `toEnglishDigits` نرمال می‌شوند، چون کاربر ممکن است
  با کیبورد فارسی ارقام فارسی یا عربی تایپ کند. این نکته باگ‌ساز کلاسیک است.

```ts
// ورودی کاربر همیشه نرمال‌سازی می‌شود
const phone = toEnglishDigits(raw).replace(/\D/g, "");
```

## اعداد و شناسه‌های لاتین در متن فارسی

شماره پیگیری، کد رهگیری و شناسه‌های لاتین در متن فارسی به‌هم می‌ریزند.
آن‌ها را در کلاس `.ltr-nums` بگذارید:

```tsx
<span className="ltr-nums">{trackingCode}</span>
```

## نیم‌فاصله

در متن‌های فارسی از نیم‌فاصله (`\u200c`) درست استفاده کنید:
«می‌شود» نه «میشود»، «هفت‌ساله» نه «هفت ساله».

## واحدها در متن

- مبالغ به کاربر همیشه **تومان** نشان داده می‌شوند، هرچند در دیتابیس ریال است.
- وزن طلا به کاربر همیشه **گرم** با حداکثر سه رقم اعشار نشان داده می‌شود.
- برای اعداد بزرگ از خلاصه‌سازی فارسی استفاده کنید: «۵۲ میلیون تومان» به‌جای «۵۲٬۰۰۰٬۰۰۰».

## تاریخ

- نمایش همیشه شمسی: «۲۵ شهریور ۱۴۰۴».
- برای زمان‌های نزدیک از عبارت نسبی استفاده کنید: «۳ روز پیش».
- ذخیره‌سازی همیشه epoch میلی‌ثانیه UTC.

## متن‌های رابط کاربری

- لحن: گرم و محترمانه، دوم‌شخص مفرد صمیمی در بخش‌های احساسی، رسمی در بخش‌های مالی.
- از اصطلاح فنی پرهیز کنید. «خطای اعتبارسنجی» ننویسید؛ بنویسید «شماره موبایل درست نیست».
- در پیام خطا همیشه بگویید کاربر **چه کار کند**، نه فقط اینکه چه چیزی غلط است.
