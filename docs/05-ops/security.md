# امنیت

## احراز هویت

- ورود با کد یک‌بارمصرف پیامکی؛ بدون رمز عبور، پس نشت رمز معنا ندارد.
- کد یک‌بارمصرف **هش‌شده** ذخیره می‌شود (HMAC با `SESSION_SECRET`).
- حداکثر ۵ تلاش برای هر کد؛ پس از آن کد سوخته می‌شود.
- محدودیت نرخ: حداکثر ۳ درخواست کد در ۱۰ دقیقه برای هر شماره.
- توکن سشن هش‌شده در دیتابیس ذخیره می‌شود؛ دسترسی خواندن به دیتابیس به‌تنهایی
  اجازه جعل سشن نمی‌دهد.
- کوکی سشن: `httpOnly`، `sameSite=lax`، `secure` در production، عمر ۳۰ روز.

## مجوزدهی

بررسی دسترسی **در دو جا** انجام می‌شود:

1. لایوت یا صفحه (برای تجربه کاربری و جلوگیری از رندر)
2. داخل Server Action (برای امنیت واقعی)

> بررسی فقط در لایوت **کافی نیست**. Server Action یک endpoint قابل فراخوانی مستقیم است.
> این یکی از رایج‌ترین اشتباهات امنیتی در پروژه‌های Next.js است.

## داده حساس

| داده | حفاظت |
| --- | --- |
| کد ملی | فقط برای ادمین مالی؛ در فهرست‌ها ماسک می‌شود |
| تصویر کودک | فایل `private`، سرو از مسیر کنترل‌شده با بررسی مالکیت |
| رسید پرداخت | فایل `private`، فقط ادمین و خود پرداخت‌کننده |
| شماره موبایل | در صفحه عمومی هدیه **هرگز** نمایش داده نمی‌شود |
| کد یک‌بارمصرف | فقط هش ذخیره می‌شود |

## آپلود فایل

- فقط انواع مجاز: `image/jpeg`، `image/png`، `image/webp`، `application/pdf`
- بررسی نوع بر اساس **محتوای فایل**، نه فقط پسوند یا هدر ارسالی کلاینت
- محدودیت حجم: ۸ مگابایت
- نام فایل ذخیره‌شده تولید‌شده توسط سرور است، هرگز نام ارسالی کاربر
- ذخیره بیرون از `public/`؛ سرو از `app/api/files/[fileId]` پس از بررسی دسترسی
- مسیر ورودی برای جلوگیری از path traversal پاک‌سازی می‌شود
- هدر HTTP باید ASCII باشد. نام فارسی فایل در `Content-Disposition` فقط با `filename*` درصدگذاری‌شده می‌آید؛ وگرنه undici خطا می‌دهد و تصویر خالی می‌شود

## صفحه عمومی هدیه

این تنها صفحه‌ای است که بدون احراز هویت به داده کاربر دسترسی دارد، پس:

- فقط با توکن غیرقابل حدس (حداقل ۱۶ کاراکتر تصادفی امن) قابل دسترسی است
- **فقط** نام کوچک کودک، سن، پیشرفت گنجینه و پیام والد را نشان می‌دهد
- هیچ شناسه داخلی، شماره تلفن، نام خانوادگی یا آدرسی افشا نمی‌شود
- در فهرست هدیه‌دهندگان، نام مشارکت‌کنندگان ناشناس نمایش داده نمی‌شود

## یکپارچگی مالی

- کد کلاینت **هرگز** مبلغ نهایی را تعیین نمی‌کند؛ همیشه سرور محاسبه می‌کند.
- شماره پیگیری رسید یکتاست تا یک رسید دو بار پذیرفته نشود.
- هر تایید یا رد پرداخت با شناسه ادمین در `audit_logs` ثبت می‌شود.
- دفتر کل طلا append-only است؛ حتی ادمین نمی‌تواند قلم قبلی را تغییر دهد.

## هدرهای امنیتی

در `next.config.ts` تنظیم شده‌اند: `X-Content-Type-Options`، `X-Frame-Options`،
`Referrer-Policy`، `Permissions-Policy`.

## لاگ

- **هرگز** در لاگ نمی‌نویسیم: کد یک‌بارمصرف، توکن سشن، کد ملی کامل، محتوای رسید.
- عملیات مالی حتماً لاگ می‌شود، اما با شناسه نه با داده حساس.
