# عملیات دیتابیس

## چرا SQLite

- بدون سرور جدا؛ یک فایل، یک بکاپ.
- برای بار مورد انتظار این پروژه کاملاً کافی است (خواندن بسیار بیشتر از نوشتن).
- هزینه عملیاتی نزدیک صفر.

## چرا درایور libsql و نه better-sqlite3

`better-sqlite3` یک ماژول نیتیو است؛ اگر روی ویندوز بیلد کنید و روی لینوکس اجرا،
باید rebuild شود. `@libsql/client` این مسئله را ندارد و مسیر مهاجرت به دیتابیس
ریموت را هم باز می‌گذارد. جزئیات در [ADR-0003](../06-decisions/0003-sqlite-with-libsql.md).

## تنظیمات اعمال‌شده روی اتصال

```sql
PRAGMA journal_mode = WAL;    -- خواندن همزمان با نوشتن
PRAGMA foreign_keys = ON;     -- در SQLite پیش‌فرض خاموش است!
PRAGMA busy_timeout = 5000;   -- صبر روی قفل به‌جای خطای فوری
PRAGMA synchronous = NORMAL;  -- تعادل سرعت و ایمنی با WAL
```

> `foreign_keys = ON` حیاتی است. SQLite به‌طور پیش‌فرض کلید خارجی را **اعمال نمی‌کند**
> و بدون این تنظیم، داده ناسازگار بی‌صدا ذخیره می‌شود.

## چرخه تغییر اسکیما

```bash
# ۱. فایل اسکیما را در src/server/db/schema/ ویرایش کنید
# ۲. فایل مایگریشن تولید کنید
npm run db:generate
# ۳. مایگریشن را اعمال کنید
npm run db:migrate
# ۴. مستندات را به‌روز کنید (data-model.md و erd.md)
```

قوانین:

- **فایل مایگریشن قدیمی هرگز ویرایش نمی‌شود.** اصلاح = مایگریشن جدید.
- فایل‌های `drizzle/` در گیت کامیت می‌شوند.
- `db:push` فقط در توسعه محلی و روی داده بی‌ارزش. **هرگز در production.**

## بکاپ

```bash
npm run db:backup
```

از دستور `VACUUM INTO` استفاده می‌شود که یک کپی سالم و فشرده می‌سازد،
حتی وقتی دیتابیس در حال استفاده است. کپی خام فایل در حالت WAL می‌تواند ناقص باشد.

بکاپ‌ها در `backups/` با نام تاریخ‌دار ذخیره می‌شوند. در production این دستور را
روی cron روزانه بگذارید و نسخه‌ها را به فضای ذخیره‌سازی خارج از سرور منتقل کنید.

## بازگردانی

```bash
# سرویس را متوقف کنید، سپس:
cp backups/haft-<تاریخ>.db data/haft.db
```

## بازنشانی محیط توسعه

```bash
npm run db:reset   # حذف فایل دیتابیس، اجرای مایگریشن‌ها، اجرای seed
```

این دستور در production عمداً مسدود است.

## نکات کارایی

- SQLite در نوشتن تک‌نویسنده است؛ تراکنش‌ها را کوتاه نگه دارید.
- برای هر ستونی که در `WHERE` یا `JOIN` استفاده می‌شود ایندکس بگذارید.
- موجودی گنجینه از جمع دفتر کل محاسبه می‌شود؛ اگر تعداد قلم‌ها زیاد شد،
  راه‌حل **کش خواندنی** است، نه شکستن قانون append-only.
