# پرسوناها

طراحی این محصول با فرض «یک کاربر» شکست می‌خورد. ما شش پرسونای متفاوت با نیازهای متضاد داریم.

## ۱. والد — کاربر اصلی

مثال: مادر آراد.

کارهایی که انجام می‌دهد: ساخت حساب، ساخت پروفایل کودک، خرید طلا، تعریف هدف، ایجاد گنجینه،
دعوت خانواده، مشاهده موجودی، تبدیل موجودی به محصول، مدیریت سفارش‌ها.

**نیاز اصلی:** کنترل و شفافیت. داشبورد او یک داشبورد مالی است، اما با روایت کودک‌محور.

## ۲. هدیه‌دهنده

مثال: خاله آراد.

این کاربر **نباید مجبور شود** اپلیکیشن نصب کند، حساب پیچیده بسازد، احراز هویت کامل انجام دهد
یا وارد داشبورد شود.

مسیر او باید دقیقاً این باشد:

```
لینک ← انتخاب مبلغ ← پرداخت ← تمام
```

**تأثیر معماری:** صفحه هدیه باید کاملاً عمومی و بدون احراز هویت کار کند. این یک الزام است، نه یک ترجیح.

## ۳. پدربزرگ و مادربزرگ

از نظر دیجیتال کم‌تجربه‌ترند اما مبالغ بالاتری هدیه می‌دهند.

**نیاز اصلی:** سادگی مطلق. فونت بزرگ، دکمه بزرگ، حداقل تعداد گام، بدون اصطلاح فنی.

```
🎁 برای آراد طلا هدیه کنید
   ○ ۵۰۰ هزار تومان
   ○ ۱ میلیون تومان
   ○ ۲ میلیون تومان
   ○ مبلغ دلخواه
   [ هدیه من به آراد ]
```

## ۴. کودک

خریدار نیست، اما **قهرمان محصول** است.

صفحه‌ای که کودک می‌بیند یک داشبورد مالی نیست؛ یک «گنج» است:

```
✨ گنج آراد
   ۳.۷۵ گرم
   «خانواده‌ات تا امروز ۳.۷۵ گرم طلا برای تو ساخته‌اند.»
```

## ۵. مدیر

باید بتواند محصولات، سفارش‌ها، کاربران، کودکان، تراکنش‌ها، قیمت طلا، موجودی، درخواست‌های تحویل،
پرداخت‌ها، هدایا، کدهای تخفیف، محتوا و پیامک‌ها را مدیریت کند.

## ۶. اپراتور و پشتیبان

از روز اول دسترسی نقش‌محور داریم، چون افزودن آن بعداً بسیار پرهزینه است:

| نقش | دسترسی |
| --- | --- |
| `super_admin` | همه چیز |
| `finance` | پرداخت‌ها، تراکنش‌ها، تایید رسیدها |
| `order_manager` | سفارش‌ها و تغییر وضعیت آن‌ها |
| `content_manager` | محصولات، مناسبت‌ها، محتوا |
| `customer_support` | کاربران، کودکان، گنجینه‌ها (فقط خواندن + پاسخ) |
| `fulfillment` | آماده‌سازی، بسته‌بندی و ارسال |
