# ADR-0001: Next.js فول‌استک به‌جای فرانت و بک جدا

**وضعیت:** پذیرفته

## زمینه

پروژه به سایت عمومی سئوپذیر، وب‌اپلیکیشن کاربر، پنل مدیریت و صفحه عمومی هدیه نیاز دارد.
تیم توسعه کوچک است.

## گزینه‌ها

۱. Next.js فول‌استک با Server Actions
۲. Next.js برای فرانت + بک‌اند جداگانه (NestJS) با API
۳. رندر سمت کلاینت خالص + API

## تصمیم

Next.js 16.3 با App Router به‌صورت فول‌استک. Server Action پیش‌فرض است؛
Route Handler فقط برای وبهوک، سرو فایل و تولید QR.

## دلیل

- سئو برای صفحات محصول و مناسبت حیاتی است؛ رندر سمت سرور رایگان به‌دست می‌آید.
- یک استقرار، یک لاگ، یک مسیر دیباگ — برای تیم کوچک تفاوت بزرگی می‌سازد.
- Server Action مرز شبکه را حذف می‌کند و تایپ‌ها از دیتابیس تا فرم پیوسته می‌مانند.
- صفحه عمومی هدیه باید سریع و بدون جاوااسکریپت سنگین باز شود؛ Server Component عالی است.

## پیامدها

آسان‌تر: تایپ سرتاسری، سئو، سرعت توسعه، استقرار.

سخت‌تر: اگر روزی اپلیکیشن موبایل نیتیو بخواهیم، به لایه API صریح نیاز پیدا می‌کنیم.
برای همین منطق کسب‌وکار در `service/` نگه داشته می‌شود و اکشن‌ها فقط پوسته نازک‌اند؛
افزودن Route Handler روی همان سرویس‌ها بعداً کم‌هزینه است.
