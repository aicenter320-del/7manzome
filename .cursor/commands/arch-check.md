# بررسی ساختار

ممیزی سلامت معماری پروژه. گزارش بده، و فقط با تایید کاربر اصلاح کن.

## گام ۱ — بررسی خودکار

```bash
npm run typecheck
npm run lint
npm run check:arch
npm run test
```

خروجی هر کدام را خلاصه کن.

## گام ۲ — بررسی مرزها

جست‌وجو کن و هر مورد را فهرست کن:

1. `import` از مسیر داخلی ماژول دیگر (`@/modules/x/domain/...` از بیرون آن ماژول)
2. `import` از `@/server/db` داخل هر `domain/`
3. `import` از `react` یا `next` داخل هر `domain/`
4. `import` از `@/modules/` داخل `shared/` یا `server/`
5. کوئری دیتابیس بیرون از `repo/`
6. `page.tsx` یا `layout.tsx` که منطق کسب‌وکار دارد
7. دور (cycle) در گراف وابستگی ماژول‌ها

## گام ۳ — بررسی قوانین دامنه

1. محاسبه مالی با عدد اعشاری یا عملگر `*` و `/` مستقیم روی مبالغ
2. `UPDATE` یا `DELETE` روی `gold_ledger_entries` یا `gold_prices`
3. ستون پولی بدون پسوند `_rial` یا ستون وزنی بدون `_mg`
4. تاریخ ذخیره‌شده به‌صورت رشته به‌جای epoch
5. Server Action که با `createAction` ساخته نشده
6. اکشنی که بررسی دسترسی ندارد

## گام ۴ — بررسی رابط کاربری

1. رنگ hard-coded (`#`، `text-gray-`، `bg-white`، `bg-yellow-`)
2. کلاس جهت‌دار فیزیکی (`ml-`، `mr-`، `pl-`، `pr-`، `text-left`، `text-right`، `left-`، `right-`)
3. عدد نمایش‌داده‌شده بدون `toPersianDigits`
4. کامپوننت `shared/ui/` که دانش دامنه دارد

## گام ۵ — بررسی همگامی مستندات

1. هر پوشه در `src/modules/` کارت مستندات در `docs/03-modules/` دارد؟
2. هر جدول دیتابیس در `docs/02-domain/data-model.md` توضیح داده شده؟
3. هر متغیر محیطی در `.env.example` و `docs/05-ops/environment.md` هست؟
4. `docs/CONTEXT.md` با وضعیت واقعی کد می‌خواند؟
5. آیا ماژولی در رجیستری هست که در کد وجود ندارد یا برعکس؟

## گام ۶ — گزارش

یک گزارش فارسی بده با سه بخش:

- **بحرانی:** نقض‌هایی که باگ مالی یا امنیتی می‌سازند
- **مهم:** نقض معماری که به بدهی فنی منجر می‌شود
- **جزئی:** ناهمگونی سبک و مستندات کهنه

برای هر مورد مسیر فایل و شماره خط بده. **قبل از اصلاح از کاربر اجازه بگیر.**
