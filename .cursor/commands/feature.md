# فیچر جدید

چرخه کامل ساخت یک قابلیت جدید در هفت منظومه. مرحله‌ای پیش برو و هیچ گامی را رد نکن.

## گام ۱ — بررسی وضعیت و جلوگیری از دوباره‌کاری

1. `docs/CONTEXT.md` را بخوان.
2. `docs/01-architecture/module-registry.md` را بخوان و مشخص کن:
   - این قابلیت به کدام ماژول موجود تعلق دارد؟
   - آیا بخشی از آن قبلاً ساخته شده؟
   - آیا ابزار کمکی مورد نیازت در فهرست «قابلیت‌های مشترک» موجود است؟
3. `docs/00-overview/glossary.md` را بخوان و نام‌گذاری‌ها را استخراج کن.
4. اگر مفهوم دامنه‌ای جدید لازم است، **اول** آن را به واژه‌نامه اضافه کن.
5. اگر ماژول جدید لازم است، مطمئن شو واقعاً در ماژول موجود جا نمی‌شود.

**نتیجه این گام را به کاربر گزارش بده و اگر ابهام هست بپرس.**

## گام ۲ — طراحی

1. اگر تصمیم معماری جدیدی لازم است، یک ADR در `docs/06-decisions/` بنویس.
2. اگر تغییر اسکیما لازم است، ابتدا جدول‌ها و ستون‌ها را طراحی کن و
   قراردادهای `docs/02-domain/data-model.md` را رعایت کن.
3. اگر ماشین حالت جدیدی هست، گذارهای مجاز را مشخص کن.
4. قوانین دامنه مرتبط را از `docs/02-domain/domain-rules.md` بازخوانی کن.

## گام ۳ — پیاده‌سازی به ترتیب

به این ترتیب بساز، نه ترتیب دیگر:

1. اسکیمای دیتابیس + `npm run db:generate` + `npm run db:migrate`
2. تایپ‌ها و منطق خالص در `domain/` **همراه با تست Vitest**
3. `repo/` — دسترسی داده
4. `schema/` — اسکیمای Zod با پیام فارسی
5. `service/` — ارکستراسیون و تراکنش
6. `actions/` — با `createAction` و سطح دسترسی صریح
7. `ui/` — کامپوننت‌های ماژول
8. `app/` — صفحه نازک که اجزا را می‌چیند
9. `index.ts` — صادر کردن فقط API عمومی

## گام ۴ — کیفیت

- چهار حالت هر صفحه: بارگذاری، خالی، خطا، داده.
- بررسی دسترسی هم در صفحه و هم در اکشن.
- RTL کامل: بدون کلاس جهت‌دار فیزیکی، بدون رنگ hard-coded.
- اعداد با ارقام فارسی، ورودی‌ها نرمال‌شده.
- `npm run verify` تا سبز شدن.

## گام ۵ — مستندات

1. کارت ماژول در `docs/03-modules/` را به‌روز یا ایجاد کن.
2. ردیف رجیستری و نمودار وابستگی را به‌روز کن.
3. `data-model.md` و `erd.md` را اگر اسکیما عوض شده به‌روز کن.
4. چک‌لیست MVP و `changelog.md` را به‌روز کن.
5. **`docs/CONTEXT.md` را به‌روز کن.**

## گام ۶ — گزارش

به کاربر بگو: چه ساخته شد، چه فایل‌هایی اضافه یا تغییر کردند، چه چیزی باقی مانده،
و آیا تصمیمی گرفتی که باید تایید کند.
