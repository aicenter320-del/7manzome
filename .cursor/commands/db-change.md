# تغییر دیتابیس

چرخه امن تغییر اسکیما. ترتیب گام‌ها مهم است.

## گام ۱ — قبل از هر تغییر

1. `docs/02-domain/data-model.md` را بخوان و ببین موجودیت مرتبط چگونه مدل شده.
2. `docs/00-overview/glossary.md` را بخوان و نام‌ها را از آن بردار.
3. مطمئن شو داده مورد نیازت در جدول موجودی نیست.
4. اگر تغییر ساختاری بزرگ است، اول ADR بنویس.

## گام ۲ — طراحی

قراردادها را رعایت کن:

- نام جدول: انگلیسی، `snake_case`، جمع
- `id` از نوع `text` با `nanoid()`
- پول: `_rial` صحیح — وزن: `_mg` صحیح — درصد: `_bp` صحیح — زمان: `_at` epoch
- بولین: `integer({ mode: "boolean" })`
- ایندکس برای هر ستون قابل جست‌وجو
- `created_at` اجباری؛ `updated_at` برای جدول‌های قابل‌تغییر
- کلید خارجی با رفتار `onDelete` صریح

بپرس: آیا این جدول append-only است؟ اگر داده مالی است، احتمالاً بله.

## گام ۳ — اجرا

```bash
# ۱. فایل اسکیما را در src/server/db/schema/ ویرایش کن
# ۲. مایگریشن تولید کن
npm run db:generate
# ۳. فایل مایگریشن تولیدشده را بخوان و مطمئن شو چیزی که می‌خواستی است
# ۴. اعمال کن
npm run db:migrate
# ۵. تایپ‌چک
npm run typecheck
```

**فایل مایگریشن قدیمی را هرگز ویرایش نکن.** اگر مایگریشن اشتباه بود، مایگریشن جدید بنویس.

## گام ۴ — به‌روزرسانی کد

1. تایپ‌های استنتاج‌شده در `src/server/db/types.ts`
2. توابع `repo/` مربوطه
3. `scripts/db-seed.ts` اگر داده اولیه لازم دارد
4. تست‌های تحت‌تاثیر

## گام ۵ — مستندات

- `docs/02-domain/data-model.md` — توضیح جدول یا ستون جدید
- `docs/02-domain/erd.md` — نمودار
- `docs/CONTEXT.md`

## گام ۶ — گزارش

بگو چه جدول یا ستونی اضافه شد، فایل مایگریشن چه نام دارد، و آیا داده موجود
تحت‌تاثیر قرار می‌گیرد یا نه.
